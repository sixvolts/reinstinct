# reinstinct-engine(1)

A from-scratch HIP inference engine for AMD Instinct MI50/MI60 (gfx906),
written in Rust. Runs Gemma 4 (dense 31B, MoE 26B-A4B) and Qwen 3.5
models straight from Unsloth Dynamic GGUF files — quantized weights stay
quantized in VRAM, kernels are compiled on demand with `hipcc`.

---

## SYNOPSIS

```
reinstinct-engine <COMMAND> [OPTIONS]
```

Commands: `inspect`, `model`, `generate`, `generate-text`,
`debug-embed`, `bench`, `hip-info`, `gpu-bench`.

---

## DESCRIPTION

The engine loads a GGUF model, keeps its quantized weights resident on
the GPU, and runs the transformer forward pass with hand-written HIP
kernels. There are two execution surfaces:

- **CPU oracle** — a reference f32 forward used to validate the GPU
  path. Slow; not intended for real inference.
- **GPU (HIP)** — the production path. Selected with `--gpu`.

The GPU path has two modes for consuming tokens:

- **Decode** — one token per forward, autoregressive. Uses an int8 KV
  cache (SageAttention-style: dp4a Q·Kᵀ, dequant-V P·V) and a
  parametric HIP graph so each step is a single graph replay.
- **Prefill** — process a whole prompt of P tokens in one pass. Weights
  are streamed once through a batched fp16 GEMM (rocBLAS HGEMM) instead
  of a per-token matvec. The prefill populates every layer's int8 KV
  cache for positions 0…P-1, so decode continues straight from position
  P. `generate-text --gpu` uses this automatically for the prompt.

### Requirements

- ROCm with `hipcc` on `PATH` (developed against ROCm 7.1).
- An AMD GPU; the kernels target `gfx906` by default (MI50/MI60).
- Kernels are compiled on first use and cached under
  `~/.cache/reinstinct/kernels/`. The cache key includes the `hipcc`
  version, so a toolchain bump recompiles automatically.

## COMMANDS

### inspect

```
reinstinct-engine inspect <PATH> [--verbose]
```

Print the GGUF header, metadata key/values, and a tensor-type
histogram. `--verbose` lists every tensor instead of the histogram plus
the ten largest.

### model

```
reinstinct-engine model <PATH>
```

Detect the architecture and parse the file into a typed model struct,
printing the resolved config. Currently typed-parses `qwen35`.

### generate

```
reinstinct-engine generate <PATH> [-t <ID>] [--tokens <ID,...>] [-k <N>] [--gpu]
```

Run a single forward pass and print the top-K logits for the **last**
position.

| Option | Default | Meaning |
|---|---|---|
| `-t`, `--token <ID>` | model EOS id | Single input token. Ignored if `--tokens` is given. |
| `--tokens <ID,...>` | — | Comma-separated token ids, fed in order. |
| `-k <N>` | 10 | How many top logits to print. |
| `--gpu` | off | Run on the GPU instead of the CPU oracle. |

### generate-text

```
reinstinct-engine generate-text <PATH> [--prompt <TEXT>] [--tokens <ID,...>]
                  [-n <N>] [--temperature <F>] [--top-k <N>] [--seed <N>] [--gpu]
```

Consume a prompt, then autoregressively sample `--steps` new tokens.

| Option | Default | Meaning |
|---|---|---|
| `--prompt <TEXT>` | — | Prompt text, BPE-encoded via the GGUF tokenizer. **`qwen35` only** — ignored by the `gemma4` path. |
| `--tokens <ID,...>` | `[eos]` | Comma-separated prompt token ids. The only prompt input for `gemma4`. |
| `-n`, `--steps <N>` | 32 | New tokens to sample after the prompt. `-n 0` consumes the prompt only. |
| `--temperature <F>` | 0.0 | Sampling temperature. `0` = greedy/argmax. |
| `--top-k <N>` | 40 | Top-k filter. `0` = full vocab. |
| `--seed <N>` | `0xC0FFEE` | PRNG seed. |
| `--gpu` | off | Run on the GPU. |

For `gemma4` models on the GPU: the prompt is consumed in one batched
**prefill** pass (which populates every layer's KV cache), then the
`steps` new tokens are generated by **decode** — a parametric HIP graph
captured once and replayed per token. Timing is reported separately for
the two phases (`prefill` / `decode`).

### debug-embed

```
reinstinct-engine debug-embed <PATH> <TOKEN> [<TOKEN> ...]
```

Dump diagnostic stats (min/max/mean/norm) for the embedding rows of the
given tokens. Useful for checking dequant correctness of the embedding
table.

### bench

```
reinstinct-engine bench <PATH> [-n <N>] [-t <ID>]
```

Run the forward pass `--iters` times and report a per-stage timing
breakdown.

### hip-info

```
reinstinct-engine hip-info [--mb <N>] [--iters <N>]
```

List HIP devices and VRAM, then time a host↔device copy round-trip.
`--mb` sets the transfer size per direction (default 64), `--iters` the
number of round-trips to average (default 8).

### gpu-bench

```
reinstinct-engine gpu-bench <PATH> [-n <N>] [-t <ID>]
```

Time GPU `forward_token` over `--iters` iterations (default 20) and
compare against the CPU baseline.

## ENVIRONMENT

| Variable | Effect |
|---|---|
| `REINSTINCT_PREFILL` | `generate-text` + `--gpu` + `gemma4`: run only the batched prefill on the prompt, print timing and top-10 logits, then exit (skips generation). A benchmark surface — the normal path already prefills. |
| `REINSTINCT_NO_GRAPH` | Disable HIP-graph capture/replay for the `gemma4` decode; run per-kernel instead. Needed when using the decode debug dump. |
| `REINSTINCT_PREFILL_DEBUG` | Print a per-layer hidden-state norm dump during `prefill_forward` (`|x[0]|`, `|x[last]|`). |
| `REINSTINCT_DECODE_DEBUG` | Print a per-layer hidden / q / attn norm dump during decode. Requires `REINSTINCT_NO_GRAPH` (a sync during graph capture is illegal). |
| `REINSTINCT_GEMMA_NO_DP4A` | Force the f32/wave64 matvec instead of the int8 `v_dot4_i32_i8` dp4a path (A/B precision check). |
| `REINSTINCT_NO_DP4A_Q4` / `_Q5` / `_Q6` / `_Q8` | Disable the dp4a path for one quant type only. |
| `REINSTINCT_OFFLOAD_ARCH` | Override the GPU arch passed to `hipcc` (default `gfx906`). |
| `REINSTINCT_GGUF_FIXTURE` | Path to a GGUF fixture for the tokenizer/test harness (test-only). |

## MODELS

Tested GGUF files live under `~/models/`:

| File | Arch | Notes |
|---|---|---|
| `gemma-4-31B-it-UD-Q4_K_XL.gguf` | gemma4 | Dense, 60 layers, head_dim 512 (full) / 256 (sliding). |
| `gemma-4-26B-A4B-it-UD-Q6_K_XL.gguf` | gemma4 | MoE, 128 experts top-8, dual FFN (shared MLP + routed experts). |
| `gemma-4-E4B-it-UD-Q6_K_XL.gguf` | gemma4 | Smaller Gemma 4. |
| `Qwen3.5-*-UD-Q4_K_XL.gguf` | qwen35 | Hybrid Gated-DeltaNet + GQA. |

Unsloth "UD" Dynamic-quant files mix quant types **per tensor** — e.g. a
nominally Q6_K MoE layer can carry a Q8_0 expert slab, and `UD-Q4_K_XL`
contains `IQ4_XS` tensors. The loader dispatches kernels per tensor on
the actual `ggml_type`.

## EXAMPLES

Inspect a model:
```
reinstinct-engine inspect ~/models/gemma4-31b/gemma-4-31B-it-UD-Q4_K_XL.gguf
```

Greedy-generate 32 tokens on the GPU from a `gemma4` prompt (token ids;
the prompt is prefilled, then decode continues):
```
reinstinct-engine generate-text ~/models/gemma4-26B/gemma-4-26B-A4B-it-UD-Q6_K_XL.gguf \
    --tokens 2,1645,1117,476 -n 32 --temperature 0 --gpu
```

Generate from a text prompt (`qwen35` models — `--prompt` is BPE-encoded):
```
reinstinct-engine generate-text <qwen-model.gguf> --prompt "The capital of France is" -n 32 --gpu
```

Benchmark the batched prefill on a 128-token prompt:
```
TOK=$(python3 -c "print(','.join(['2']+[str(100+i) for i in range(127)]))")
REINSTINCT_PREFILL=1 reinstinct-engine generate-text <model.gguf> --tokens $TOK -n 0 --gpu
```

A/B the dp4a matvec against the f32 path:
```
REINSTINCT_GEMMA_NO_DP4A=1 reinstinct-engine gpu-bench <model.gguf> -n 50
```

Trace per-layer norms through decode (graph disabled):
```
REINSTINCT_NO_GRAPH=1 REINSTINCT_DECODE_DEBUG=1 \
    reinstinct-engine generate-text <model.gguf> --tokens 2,1645 -n 1 --gpu
```

## PERFORMANCE (gfx906, MI50 32 GB)

Indicative, single MI50:

| Workload | Throughput |
|---|---|
| 26B MoE decode | ~64 tok/s (~15.4 ms/token) |
| 31B dense decode | ~19.5 tok/s (~51 ms/token) |
| 26B prefill, P=128 | ~12.5 ms/token |
| 31B prefill, P=128 | ~16 ms/token |
| 31B prefill fixed cost | ~0.99 s (weight dequant-to-fp16, amortized over P) |

Decode tuning that mattered: int8 dp4a matvec, ROWS=2 per wavefront
(the matvec was occupancy-starved at ROWS=8), int8 KV cache, and a
parametric HIP graph. The forward is matvec-bandwidth-bound on this
ROCm/gfx906 — the graph buys ~4%.

Prefill: weights are dequantized to fp16 once per pass and streamed
through rocBLAS HGEMM; the 26B's routed experts use a grouped GEMM so
each expert's weight is L2-resident across all its tokens. The
`PrefillGemm` context pools the dequant scratch and modules so the
per-weight cost is paid once, not per call.

## NOTES

### Prefill vs. decode numerics

The decode path projects via int8 dp4a matvec; the prefill path
projects via fp16 HGEMM. These are different precisions. For the 26B
the two agree (same top-token set). For the **31B dense** model they
diverge at P>1: the ~0.1%-per-layer rounding difference accumulates
over 60 layers and is then amplified by a near-cancellation in the
final layer (a ~70-magnitude residual collapses to ~7), flipping the
top token. This is a numerical-sensitivity artifact, not a bug — the
prefill attention tracks decode within ~0.1% per layer. Bit-matching
would require projecting the prefill via int8 matvec, which would
defeat the GEMM batching. The chosen direction is int8 decode as the
production path.

### CPU oracle caveat

The CPU forward is a validation oracle, not ground truth for every
model. For the dense 31B it disagrees with **both** GPU paths — do not
use the CPU 31B result as a correctness reference. The 26B has a
validated CPU oracle; the 31B does not.

### Diagnostics

`REINSTINCT_PREFILL_DEBUG` / `REINSTINCT_DECODE_DEBUG` emit per-layer
norm dumps to stderr. They are the fastest way to localize a
forward-pass divergence to a specific layer.

---

## LIMITATIONS

- GPU kernels target `gfx906`; other archs need `REINSTINCT_OFFLOAD_ARCH`
  and are untested.
- The `gemma4` `generate-text` path takes `--tokens` only — `--prompt`
  text encoding is wired for `qwen35` but not `gemma4`.
- `model` typed-parses `qwen35` only; `generate` / `generate-text`
  cover `gemma4` and `qwen35`.
- Single-GPU only.
